# SITL run — 2026-10-26 (ADR-019 follow-up: z re-zeroed at home)

Full T06–T12 run after `autopilot_bridge` started shifting z by home (VehicleState out,
setpoints in), so `position_enu_m.z` is height above home rather than above the EKF origin.
New test T12 (`sim/tests/t12_home_offset.py`). Same stack as 2026-09-28: PX4 v1.16.0 SITL
`gz_tiltrotor` (4020), Gazebo Harmonic `shark_isr_coastal`, MicroXRCEAgent udp4:8888, ROS 2
Humble. Exactly one instance of each node checked before each batch.

| Test | Result | Notes |
|---|---|---|
| T12 (first run) | PASS | on the ground z = -0.00; climbed to 30 m; DO_SET_HOME +20 m → z ~10 at once, climbed back to 30 m above new home |
| T06 | PASS | min=max=mean=30.00 m |
| T07 | PASS | PX4 exited OFFBOARD in 5.1 s → nav_state=2 |
| T08 | PASS | nav_state=5 (RTL) |
| T09 | PASS | on a restarted sim — see findings |
| T10 | PASS | gate held on 5-frame burst, fired on 30-frame stream |
| T11 | PASS | TRACK at t+70.0 s, 297 detections |
| T12 | PASS | home 0.15 m AMSL, z = -0.00 on the ground; same shift and recovery as the first run |

Findings:
- PX4 publishes `home_position` only when home changes (arming, takeoff, DO_SET_HOME), and the
  uXRCE-DDS writer keeps no history, so a bridge started after boot never receives it. The bridge
  therefore takes home = the vehicle's own position while disarmed (what PX4 itself does to a
  landed vehicle), latches it at arming, and applies `home_position` updates while armed.
- After T08's RTL the vehicle sat landed and armed (the known no-auto-disarm finding from
  2026-09-03 / 2026-09-28), so T09–T12 timed out waiting for IDLE. This time PX4 also ignored
  `CMD_DISARM` and even `commander disarm` from its own console, and its console output had
  stopped ("Interrupted system call"). The whole sim was restarted, and T09–T12 then passed.
  T06–T08 ran on the first sim instance; T09–T12 on the second.
- The bridge restarted after T07 (vehicle armed in PX4's failsafe) came up with the vehicle
  disarmed again by then, so the "armed with no home" path was not exercised in SITL.
