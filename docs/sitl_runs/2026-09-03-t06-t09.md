# SITL run — 2026-09-03 (T06–T09)

Second session the same day, after `docs/sitl_runs/2026-09-03-t10-t11.md`. Re-runs the rest of
the T06–T11 campaign so all six integration tests have committed console output, not just
transcribed claims (per `docs/SITL_PROCEDURE.md`'s open status note).

**Stack:** same PX4 SITL / Gazebo / DDS agent setup as the T10/T11 session. T06 and T07 need
only `autopilot_bridge` (verified 1 process before T06); T07 kills the bridge by design, so it
was restarted and joined by `guidance_node` + `mission_node` (verified 3 processes) before T08/T09.

**Real environment finding, not a code defect:** after T08's RTL, the vehicle landed (AGL settled
to ~0.1–0.2 m) but PX4 did not auto-disarm within ~4 minutes of waiting — `nav_state` stayed
`5` (RTL) and `armed` stayed `true`, so `mission_node`'s RETURNING→IDLE transition (which waits
on `armed == False`) never fired and blocked T09 (which needs IDLE to start). Manually disarmed
via the already-implemented `AutopilotCommand.CMD_DISARM` service to unblock it — a legitimate
operator action, not a workaround in the ROS 2 code. Worth checking at hardware bring-up whether
this VTOL airframe's landing detector reliably auto-disarms after RTL, or needs a longer wait /
an explicit disarm step in the mission procedure.
