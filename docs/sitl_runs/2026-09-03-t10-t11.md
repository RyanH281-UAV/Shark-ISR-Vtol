## Addendum — 2f80db6: T10/T11 re-confirmed with a real fix in place

The runs above were valid but incomplete: T10's negative-burst check only worked because
perception happened not to be running. Reproduced against a live user session started via the
standard 5-tab launcher (perception running throughout, as normal): a random mock detection
(`mock_detection_prob` default 2%/frame) landing on the TRANSIT→SEARCH boundary looked
indistinguishable from the confidence gate failing.

Root cause: `detector_node` declared `mock_detection_prob`/`mock_burst_frames` as parameters but
never re-read them after `__init__` — `ros2 param set` on the running node returned success and
silently changed nothing. Fixed with a proper `add_on_set_parameters_callback`; T10 now mutes
`mock_detection_prob` for its own duration and restores it in its existing `finally` block.

previously-failing scenario):

## Addendum 2 — c04f335: the first fix wasn't the whole fix

Ryan re-ran T10 after `2f80db6` and hit the same failure. `2f80db6` made `mock_detection_prob`
live-tunable, but a burst already in flight when the mute call lands is tracked by its own
independent counter (`_mock_burst_remaining`) and kept firing its remaining frames (up to ~3s)
regardless — muting stopped new bursts, not the one already running. Also found two `detector_node`
processes running at once (a stale one from an earlier launch never cleaned up) while
investigating — killed both, relaunched one, unrelated to the fix itself but worth ruling out
first. `_on_params_change` now zeroes `_mock_burst_remaining` when the probability changes.
