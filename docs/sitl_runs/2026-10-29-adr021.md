# SITL run — 2026-10-29 (ADR-021: detection sigma from geolocation)

T10 + T11 after `guidance_node` switched the positive-detection map update from a fixed 25 m
sigma to each detection's own `position_std_m` floored at `detection_sigma_min_m` = 5 m. T10
injects `geo_valid=False` detections (fallback path, 25 m); T11's mock detector publishes
geolocated detections (new path). Same stack as 2026-10-26: PX4 SITL `gz_tiltrotor` (4020),
Gazebo Harmonic `shark_isr_coastal`, MicroXRCEAgent udp4:8888, ROS 2 Humble. Exactly one
instance of autopilot_bridge, guidance_node, mission_node, detector_node and px4 checked before
the batch; all processes killed afterwards.

| Test | Result | Notes |

| T10 | PASS | gate held on 5-frame burst, fired on 30-frame stream; IDLE→TRANSIT→SEARCH→TRACK→RETURN in 16.3 s |
| T11 | PASS | first detection `geo_valid=True`; TRACK at t+12.5 s, 29 detections |

Findings:
- No behaviour change visible at the phase level, as expected: SEARCH → TRACK is driven by the
  confidence gate (ADR-016), not by the belief map. The sigma change shows up in where
  `persistent_patrol`/`bayesian_greedy` steer after a sighting, which no SITL test asserts yet.
- `colcon test` for `shark_isr_guidance` errors before collecting (anyio pytest plugin in
  `~/.local` imports `_pytest.scope`, absent from the system pytest). Unit tests run clean with
  `python3 -m pytest -p no:anyio`: 56/56. Environment issue, not code.
